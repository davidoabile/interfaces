# Own AI: complete linked mockups

[AI accounts](../global-mockups/index.html#macos/own-ai-accounts/light) · [Persona selection](../global-mockups/index.html#macos/own-ai-selector-career/light) · [Feedback styles](../global-mockups/index.html#macos/own-ai-feedback-guide/light)

The first macOS sample was approved. The user requested the remaining screens, better recovery UX, and explicit danger, warning, success and info feedback. This is the current source; `../own-ai-review/` retains the approved reference.

**188 linked states / 2,632 SVGs**, seven platform layouts and light/approved warm-charcoal themes. Manage API accounts in Settings → Privacy & AI access → AI accounts, then select an account in each Persona. **Sigmar AI is the default.** Existing Persona identity editors and the creation wizard link to the appropriate selection screen. Adding a key alone does not attach it to a Persona or grant data access. Registered AI clients remain a separate concern.

Covered journeys: optional setup/empty/loading; provider choice; draft disclosure; masked key entry; five-digit PIN; checking/success; invalid key, credit, model, rate/connection errors; account detail; attached-Persona review; replacement with the old key retained until validation succeeds; removal impact, explicit switch choice, PIN and pending/failed/confirmed removal; provider run failures; per-Persona Anthropic/OpenAI selection, review, pending/failure/confirmed choices and return to Sigmar AI; illustrative daily caps, validation, review/save/recovery/reset; unsupported request types. Every existing Persona and the new-Persona draft has a scoped selection journey. Unsupported provider requests stop with an explanation.

These are finite illustrative snapshots, not a persistent application. Keys are masked placeholders; suffixes and usage values are fabricated display metadata. No secrets, live provider calls, PIN verification, billing changes, account mutations or provider emails occur. A real UI must bind the selected account, affected Persona list and return destination to live state. Draft selections must persist through the wizard and only become effective on confirmed submission.

The seven Sponsor decisions in [PR #382](https://github.com/davidoabile/apcce/pull/382) remain separate from visual approval: custody, permitted credentials/OAuth access, charging and caps, final provider disclosure copy, fallback, platform runtime credentials, and rollout order. The proposed 200-request maximum and 100-request lower cap are explicitly illustrative in the gallery; neither is an approved production policy. No claim is made about exact provider retention or training terms. This implementation only illustrates API keys. It does not implement the PR's member-global choice: the user's latest direction is per Persona, which requires matching architecture changes.

The shared [feedback component](../shared-feedback.cjs) defines semantic text/background/border tokens, icons and live-region roles for both themes. Danger explains a blocked/failed action; warning precedes consequences or a recoverable limitation; success follows confirmation; info explains progress or context. Messages state what happened, what remains, and what to do. Critical messages remain visible; cancellation is explicit; colour is never the only signal. Related test outcomes appear outside the customer interface in the gallery.

Build: `node admin/own-ai-mockups/build.cjs`, then `node admin/global-mockups/gallery.cjs`. The complete pipeline is `node admin/global-mockups/build-all.cjs`.
