# Persona media and wizard correction

Current entry points: [Persona management](../global-mockups/index.html#macos/persona-home/light), [creation wizard](../global-mockups/index.html#macos/persona-wizard-1/light), [media library](../global-mockups/index.html#macos/persona-media-career-library/light), [upload](../global-mockups/index.html#macos/persona-media-career-upload/light).

The user identified repeated generic feedback, a hard-to-find creation wizard, and missing media-library/upload UX. The correction adds visible gallery shortcuts and overview actions, explicit step labels and back navigation, and an actual grid/preview/upload design rather than a preselected-file text list. Alert titles and details now describe each event; rendering refuses a missing feedback title.

`media.cjs` supplies 216 additional states across the six existing Personas and the draft, including six draft extraction reviews. These cover image/document filters and search, empty/no-results views, upload dropzone and supported formats, native-style file selection, selected-file review, progress, interruption/retry, unsupported types, cancellation, previews, image crop/confirmation, camera/permission guidance, document attachment and per-section extraction review. Existing section upload and identity image controls use the new surfaces. Every ordinary link keeps its Persona, platform and theme. No library deletion or broad sharing is introduced.

The illustrative media items are `Profile landscape.png` and `example-persona-notes.pdf`. Thumbnails and page previews are editable vector samples, with content colours retained in dark mode; no personal photographs or documents were copied. The native file-picker mockups are review surfaces, not access to the user's actual files. All uploads, progress, files and outcomes are examples. Numeric file-size limits are not invented; a working implementation must obtain and show its actual policy.

Flutter grounding: `/Users/doabile/workspace/hedgetech/sigmar-investment-app/lib/src/feature/library/` contains the library model, browsing and creation designs. Its `LibraryItem` comment records seeded UI data and pending library persistence in that checkout; `CreateLibraryItemPage` includes preview file-selection controls. This does not establish the status of another branch. The implemented input paths in `feature/home/domain/resume_source.dart` cover files, camera, photo library, paste and voice; `resume_import.dart` accepts PDF/DOCX/TXT. The native-sync checkout's `feature/personas/presentation/persona_view_page.dart` invokes those inputs and reviews extracted content before save. These mockups restore the missing UX without claiming a new backend implementation.
